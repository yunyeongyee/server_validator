# 사용자 흐름 · 버튼 동작 정의 v0.3

이 문서는 **검토할 목업 제안**입니다. 서버 영업·기술 담당자가 원문을 입력하고, 추출을 확인한 뒤, 판정을 검토하고 실제 이미지에 구성을 표시하는 흐름을 정의합니다. OpenAI 정형 추출·웹 조사는 선택적 연결입니다. 키가 없으면 예비 추출과 미실행 조사 요청으로 동작합니다. 실제 베이 자동 감지·최종 승인은 아직 연결하지 않았습니다.

## 전체 흐름: 통합 비교 화면

별도 단계 화면을 오가는 대신 원문·추출·판정·이미지를 같은 작업 화면에서 검토합니다. 위쪽 원문 입력은 분석 후 접히며 **원문 보기·다시 분석**으로 다시 펼칩니다. 왼쪽 공통 사양 표의 한 행에서 요구조건, 견적 명시값, 예비 판정을 비교합니다. 각 행의 **근거**는 그 항목의 실제 비교 결과만 보여줍니다. 검토 완료 표시는 충족 판정과 별개입니다.

오른쪽 전면·후면 이미지를 누르면 상세 편집 모달이 열립니다. **구성**에서는 서버 이미지 선택과 견적 부품 배정, **라벨·연결선**에서는 라벨 텍스트·굵게·자동 배치·수평 정렬·연결선 실선/점선·굵기, **좌표 보정**에서는 영역 추가·이동·숫자 좌표·확정을 제공합니다. 상단 확대/맞춤은 편집 시야만 바꾸고 좌표값은 유지합니다. 변경은 자동 반영되며 **편집 완료**, X, Esc는 변경을 유지하고 모달을 닫습니다. 하위 보관함/입력 모달을 닫으면 편집 모달로 돌아옵니다.

원문 수정 시 기존 추출·판정·부품 배정은 즉시 해제합니다. 수동 추출값 수정은 근거를 기록하고 판정을 다시 계산합니다. 이미지 배치가 호환성의 증거가 되지는 않습니다. 원문 분석 전에도 실제 이미지 선택과 좌표 작업은 가능하지만 견적 부품 배정은 분석 후 가능합니다.

## 상태와 표현

| 대상 | 상태 | 의미 |
|---|---|---|
| 추출 항목 | 원문 검토 필요 / 검토 완료 | 사람이 원문과 필드 값을 대조했는지 |
| 요구 비교 | 예비 충족 / 미충족 / 확인 필요 | 명시된 조건을 비교한 결과. 원문 검토 완료와 독립 |
| 장착 호환 | 검증 대기 / 장착 불가 | 공식 가이드와 선택한 실제 섀시 구성의 근거가 필요한 별도 판정 |
| 이미지 | 미선택 / 보정 중 / 좌표 확정 / 구성 배치안 | 배치 상태. 장착 호환 판정의 근거가 아님 |
| 조사 | 조사 요청 저장 / 미실행 | 키가 없으면 외부 검색을 실행하지 않음 |

최종 승인 기능은 다음 구현에서 별도로 제공합니다. 모든 필수 원문의 검토, 비교 기준 확정, 필수 미추출·확인 필요 해소, 공식 지원 검증을 승인 조건으로 제안합니다. 이미지가 그럴듯하게 배치된 사실만으로 승인하지 않습니다.

## 공통 영역

| 버튼/조작 | 활성 조건 | 누르면 | 취소·실패 처리 |
|---|---|---|---|
| Server Validator 로고 | 항상 | 같은 화면의 원문 영역으로 이동 | 입력값 보존 |
| 위쪽 검토 영역 버튼 | 항상 | 같은 화면의 해당 영역으로 이동. 이미지 구성은 모달 열기 | 입력값 보존 |
| 임시 저장 | 항상 | 원문·수정값·기준·이력·보정을 현재 브라우저에 저장 (변경 시에도 자동 임시 저장) | 저장 공간 부족 안내. 다른 PC와 자동 동기화하지 않음 |
| 이미지 보관함 | 항상 | 실제 이미지 이름·출처·미리보기 열기 | 닫기/Esc로 원래 화면 복귀 |
| 판정 원칙 | 항상 | 누락·모호성·호환·출처의 처리 원칙 설명 | 닫기/Esc로 복귀 |
| 대화상자 × / 닫기 / 취소 | 대화상자가 열렸을 때 | 저장하지 않고 닫기 | 현재 작업 유지 |

‘OpenAI 없이 실행’/‘AI 설정됨’과 ‘목업’은 현재 상태 표시입니다. 키 설정은 실제 API 인증 성공을 뜻하지 않습니다. 연결이 된 것처럼 클릭 상태를 바꾸지 않습니다.

## 1. 문서 입력

요구사항과 견적을 나란히 입력합니다. 원문 표·HTML 줄바꿈은 유지하고 추출용 텍스트만 정규화합니다. 한쪽 문서당 최대 60,000자입니다.

| 버튼/필드 | 누르면/변경하면 | 세부 조건 |
|---|---|---|
| 고객 요구사항 입력 | 고객 원문 입력·붙여넣기 | 글자 수 실시간 표시 |
| 견적사항 입력 | 견적 원문 입력·붙여넣기 | 서버 모델/수량이 없으면 추정하지 않음 |
| 예제 불러오기 | 고객이 제공한 R760 예제를 두 입력칸에 채움 | 현재 문서가 있으면 교체 확인. 확인 시 기존 추출 결과 초기화 |
| 예제 불러오기 확인 / 취소 | 예제로 바꾸기 / 현재 문서 유지 | 이력은 유지 |
| 초기화 | 초기화 확인 창 | 두 원문·분석 결과·검토 이력·조사 요청 제거. 보관함·보정 유지 |
| 초기화 확인 / 취소 | 위 항목 삭제 / 유지 | 브라우저 임시 저장도 반영 |
| 두 문서 예비 분석 | 원문을 보존하고 선택한 방식으로 추출 → 같은 화면의 비교표 표시 | 빈 문서면 진행하지 않음. 처리 중 재클릭 방지 |
| 다시 분석 / 취소 | 현재 원문으로 새 추출 / 기존 결과 유지 | 수동 수정·검토 상태가 초기화된다고 미리 안내 |

원문을 재분석하면 이전 견적에 연결했던 부품 배정·이미지 연결을 해제하고, 서버 이미지와 보정 영역은 유지합니다. 견적 항목의 필드를 수동 수정해도 그 항목의 기존 이미지 연결·배치를 해제하여 이전 부품이 남지 않게 합니다.

분석 방식에서 자동·규칙·OpenAI를 선택할 수 있습니다. 키/SDK가 없으면 예비 추출로 처리합니다. 형식 검증·원문 근거 검증 실패 시 일부 결과를 섞어 충족 판정하지 않고, 해당 문서의 검토 필요를 표시하는 흐름을 제안합니다.

## 2. 추출값 검토

같은 열 구조로 `구분 / 고객 요구사항 / 견적사항 / 예비 판정`를 표시합니다. 각 부품을 독립 항목으로 표시하고, 원문에 수량이 없으면 ‘수량 미명시’로 남깁니다. CPU 총 코어와 메모리 총용량은 개별 값 × 명시 수량으로 계산한 값임을 표시합니다.

| 버튼/조작 | 누르면/변경하면 | 세부 조건 |
|---|---|---|
| CPU 코어 기준 | 미지정 / 서버 전체 / CPU당 선택 | 선택 이력 기록. 미지정이면 코어 충족 보류 |
| 메모리 기준 | 미지정 / 서버 전체 / 모듈당 선택 | 미지정이면 모듈 수량 없는 요구 용량의 충족 보류 |
| 각 항목 검토 | 원문 근거·추출 필드·확인 항목 대화상자 | 원문 근거는 수정하지 않음 |
| 검토 대화상자 필드 | 해당 부품 필드만 편집 | 빈칸은 null. 수량·코어·포트는 음수가 아닌 정수 |
| 원문과 대조하여 검토 체크 | 사람이 검토했음을 지정 | 값이 맞는지 확인한 상태이며, 요구 충족과 별개 |
| 검토 저장 | 변경 사유 기록, 저장, 예비 비교 재계산 | 값이 바뀌면 수정 사유 필수. 미체크 저장도 허용 |
| 직접 확인 후 추가 | 해당 문서·구분의 새 항목 입력창 | 근거와 사유 필수. 수동 입력 표시 |
| 누락 항목 추가 | 문서·구분 선택창 | 입력하기 → 원문 근거와 세부값 입력 |
| 입력하기 / 추가 | 항목 입력창 열기 / 공통 사양에 추가 | 자동 생성 근거를 넣지 않음 |
| 미추출 원문 펼치기 | 추출하지 못한 원문 표시 | 원문은 삭제하거나 충족으로 숨기지 않음 |
| 누락 항목 검토 → 항목 추가 | 원문 대조 후 누락 항목 보완 | 미추출 원문은 최종 검토 대상으로 계속 보존 |
| 변경 이력 | 누가 아닌 무엇·언제·왜 바꿨는지 표시 | 시간은 한국 시간(KST) |
| 이력 내보내기 | JSON 파일 저장 | 실제 API 검색 이력과 혼동하지 않음 |
| 문서 입력 | 같은 화면의 원문 영역 펼치기 | 원문을 수정하면 기존 결과 해제 |
| 판정 상세 보기 | 오른쪽 판정 영역으로 이동 | 미검토 개수와 예비 판정 상태를 유지. 최종 승인으로 표시하지 않음 |
| 항목별 근거 | 해당 구분의 예비 판정 근거 모달 열기 | 요구값·견적값·판정 이유 표시 |

OpenAI 웹 조사 사용 시: 허용된 공식 도메인 검색 → 인용문·URL·문서 개정일·표 위치 제시 → 사용자가 근거 확인 → 추출/판정 보완. 검색 응답을 원문 견적의 모델이나 수량으로 자동 복사하지 않는 흐름을 제안합니다.

## 4. 서버 이미지 구성

전면과 후면의 이미지·좌표·확정 상태는 별도로 관리합니다. 실제 스텐실의 내장 이미지만 사용하며, 서버·부품 그림을 임의로 그리지 않습니다. 가이드·영역 사각형·라벨·연결선은 편집용 표시입니다.

| 버튼/조작 | 활성 조건 | 누르면/변경하면 |
|---|---|---|
| 전면 / 후면 | 항상 | 해당 방향의 실제 이미지·보정 표시. 선택 영역 해제 |
| 서버 이미지 선택 / 변경 | 항상 | 보관함을 서버 기준으로 열고 모델·방향 제한 |
| 스텐실 가져오기 | 항상 | VSSX/VSDX 선택 → 지원 내장 이미지 추출 → 보관함 추가 |
| XR 이미지로 편집 연습 | 실제 대상 모델 이미지가 없는 빈 상태 | 실제 XR 이미지를 사용해 보정 흐름 연습. 견적 모델과 별개로 명시 |
| XR 연습 종료 | 연습 중 | 확인 후 연습 좌표 초기화, R760/R660 이미지 선택으로 복귀 |
| 시각화 대상 모델 | 항상 | R760/R660 변경. 이미지/좌표 초기화 확인. 문서의 모델은 바꾸지 않음 |
| 보정 도움말 | 항상 | 좌표·다중 선택·라벨·저장 절차 안내 |
| 베이 자동 감지 | 전면 실제 이미지 선택 후 | 목업에서는 예정 흐름 안내. 현재 감지 미실행 |
| 직접 영역 추가 | 감지 안내 창 | 수동 영역 추가 대화상자 |
| + 베이 영역 / + 슬롯·PSU 영역 | 이미지 선택 후 | 종류·이름·베이 인치 입력 → 미확정 영역 생성 |
| 영역 추가하고 보정 | 이름 입력 후 | 기본 위치에 편집 영역 추가. 사용자가 실제 위치로 보정 |
| 영역 드래그 / X·Y·너비·높이 | 선택 영역이 있을 때 | 좌표 수정 → 확정 해제 |
| 영역 선택 드롭다운 | 영역이 있을 때 | 해당 영역 선택 |
| Shift+클릭 | 영역이 있을 때 | 선택에 추가/제거 |
| 방향키 / Shift+방향키 | 선택 영역·입력창 밖 | 좌표 보정 탭: 영역을 1 / 10 단위 이동하고 확정 해제. 라벨 탭: 라벨만 이동 |
| 좌표 확정 | 영역이 있고 좌표가 편집 범위 안일 때 | 해당 방향 좌표를 확정. 이후 부품 배치 가능 |
| 빈 베이 필러 | 전면 빈 베이 선택 후 | 필러 기준 보관함 열기. 실제 필러 이미지 연결 |
| 라벨 텍스트 | 선택 영역이 있을 때 | 표시할 부품명 편집 |
| 라벨 드래그 | 라벨이 있을 때 | 라벨 위치만 변경. 연결선 종점 함께 이동 |
| 라벨 자동 배치 | 영역이 있을 때 | 라벨 간격 정리 및 연결선 생성 |
| 굵게 | 라벨 탭·선택 영역이 있을 때 | 선택 라벨 굵기 토글 |
| 라벨 수평 정렬 | 라벨 탭·2개 이상 선택 | 선택된 영역 중 첫 영역의 라벨 높이에 맞춤 |
| 연결선 실선/점선/숨김 | 라벨 탭·선택 영역이 있을 때 | 선택 연결선 표시와 종류 변경. PNG에도 반영 |
| 선 굵기 1~4px | 라벨 탭·선택 영역이 있을 때 | 선택 연결선 굵기 변경. PNG에도 반영 |
| 확대 / 축소 / 100% | 모달 상단 | 100~200% 시야 확대 또는 기본 맞춤. 실제 좌표값 유지 |
| 편집 완료 / X / Esc | 편집 모달 | 변경을 유지하고 비교 화면으로 복귀 |
| 선택 삭제 | 영역 선택 후 | 삭제 확인 → 선택 좌표와 배치 제거. 견적 부품은 유지 |
| 가이드 / 스냅 / 연결선 | 가이드·스냅은 항상, 연결선은 선택 시 | 격자 표시 / 5단위 스냅 / 선택 라벨 연결선 토글 |
| 견적 부품 이미지 연결 / 변경 | 분석 후 | 해당 부품 분류 기준 보관함 열기. OCP/PCIe 불일치 차단 |
| 모델 토큰으로 자동 연결 | 분석 후 | 이름 토큰이 유일하고 형식도 일치하는 카드만 연결. 여러 후보는 보류 |
| 배치 | 이미지+좌표 확정 후 | 해당 부품과 같은 형식의 빈 영역 선택 창 |
| 1개 배치 | 같은 형식의 빈 영역이 있을 때 | 선택 영역에 이미지/라벨 배치. 명시 수량 이상 배치 방지 |
| 보정 저장 | 항상 | 브라우저에 좌표·연결 저장 |
| 보정 파일 내보내기 | 항상 | 기준 좌표계·이미지 식별자·좌표·연결을 JSON으로 저장 |
| 보정 파일 가져오기 | 항상 | 스키마·좌표·이미지 존재 확인 → 교체 확인 → 미확정 상태로 가져오기 |
| PNG 저장 | 실제 이미지 선택 후 | 실제 이미지+연결한 실제 부품 이미지+라벨·연결선 합성. 배치안/연습 워터마크 |
| 판정 확인 | 항상 | 편집 모달을 닫고 판정 영역으로 이동 |
| 검토 요약 확인 | 항상 | 원문 검토·판정·이미지 상태 요약. 최종 승인과 구분 |
| 판정으로 돌아가기 / 계속 검토 | 요약 창 | 편집 모달을 닫고 판정 영역으로 이동 / 요약 닫기 |

CPU·메모리는 전면/후면에서 내부가 보이지 않으므로 ‘내부 구성 라벨’ 영역으로만 표시합니다. 실제 내부 이미지를 사용하기 전에는 CPU를 외부 슬롯에 그려 넣지 않습니다.

보정 파일에는 견적 필드의 SHA-256 식별값을 넣습니다. 같은 견적이면 부품 연결을 유지할 수 있고, 다른 견적이면 좌표를 가져오되 부품 연결·배정은 해제합니다. 이전 문서의 배열 순서를 새 견적 부품에 자동 적용하지 않습니다.

## 이미지 보관함

| 버튼/조작 | 동작 | 검증/예외 |
|---|---|---|
| 이름·모델 검색 | 원본 이름과 alias 필터 | 모델 이름이 비슷하다는 이유로 자동 선택하지 않음 |
| 전체 / 서버 / 디스크 / PSU / 필러 / NIC·HBA / 기타 | 분류 필터 | 부품 연결 시 다른 분류는 선택 불가 |
| 스텐실 가져오기 | 사용자 원본 파일 업로드 | 최대 128MB. ZIP 크기·XML 구조 한도 확인 |
| 이미지 추가 | 실제 PNG/JPG/WebP 한 장 선택 | 20MB, 4천만 픽셀 이하. 브라우저 보관함 저장 |
| 이름·분류·모델·방향·장착 형식 입력 | 연결 기준 메타데이터 지정 | 실제 서버 이미지에는 모델 필수 |
| 실제 이미지 확인 체크 | 파일/이름/형식을 확인했음 지정 | 체크 전 저장 불가 |
| 이미지 저장 | 브라우저에 원본 저장 | 저장 공간 부족 안내 |
| 이미지 카드 선택 | 보기 모드: 원본 미리보기 / 연결 모드: 대상에 연결 | 서버 모델/방향, 부품 분류, OCP/PCIe 불일치 차단 |
| 직접 확인 후 연결 | 장착 형식 미명시 이미지의 확인 창 | 사람이 확인한 경우만 연결. 공식 장착 판정은 보류 |
| 미리보기 → 보관함 | 이전 검색 흐름으로 복귀 | 원문 출처·내장 경로 표시 |
| 다른 파일 선택 | 가져오기 실패 창 | 원본 VSSX/VSDX 또는 Visio 내보내기 PNG 선택 |

지원 내장 이미지가 없으면 XML 도형을 임의로 그리지 않습니다. Visio에서 해당 원본 이미지를 PNG로 내보내는 대안을 안내합니다. 전체 페이지/마스터 재현과 내장 이미지 추출은 구분합니다.

## 목업으로 결정할 사항

1. 원문 검토를 항목별로 하는 현재 방식이 실제 업무에 적절한가?
2. 미검토 상태에서 예비 판정/배치안까지 이동할 수 있는가? 최종 승인은 별도 차단하는가?
3. 수동 추가 시 원문/외부 근거와 사유를 필수로 받는가?
4. CPU 코어·메모리 기준은 문서 전체 기준인지 항목별 기준이 필요한가?
5. 시각화 대상이 요구 모델이고 견적 모델은 미명시인 경우 배치안을 허용할 것인가?
6. 최종 보고서는 한 화면 요약, 상세 근거, PNG 중 무엇을 기본 제공할 것인가?

현재 목업은 위 표의 기본 흐름으로 동작합니다. 업무 흐름을 검토한 뒤 AI 연결과 공식 사양 검증을 진행합니다.
